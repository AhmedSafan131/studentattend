UniAttend Frontend Documentation
================================

Last reviewed: 2026-05-11

Project Summary
---------------
UniAttend is a React frontend for a university attendance system. It supports three main user roles:

- Admin: manages staff/doctor accounts, student records, locked student accounts, permissions, attendance records, and reports.
- Staff / Doctor: starts live lecture attendance sessions, displays QR codes, reviews live attendance, manages permitted student records, and exports reports.
- Student: scans QR codes, reviews persisted attendance history, and manages profile information.

The frontend is located in `FrontEndProject`. The app is built with Create React App, React Router, Redux Toolkit, Socket.IO, XLSX import/export tools, ZXing QR scanning, and a Laravel API backend.


Runtime Commands
----------------
- Install dependencies:
  `npm install`

- Start React only:
  `npm start`

- Start Socket.IO bridge only:
  `npm run server`

- Start React and Socket.IO bridge together:
  `npm run dev`

- Start React over HTTPS for mobile camera testing:
  `npm run start:https`

- Start HTTPS React and Socket.IO bridge together:
  `npm run dev:https`

- Build production assets:
  `npm run build`

- Run tests:
  `npm test`


Backend And Realtime Endpoints
------------------------------
- Laravel API base URL:
  `src/utils/Axios.js`

- Current default API URL:
  `http://localhost:8000`

- API URL override:
  Set `REACT_APP_API_BASE_URL` before starting React.

- Socket.IO bridge URL:
  `src/utils/constants.js`

- Current socket URL:
  `http://localhost:3001`

- Socket health endpoint:
  `http://localhost:3001/health`

Important note: if Laravel is served on a different port, update `REACT_APP_API_BASE_URL` or the default in `src/utils/Axios.js`.


Technology Stack
----------------
- React 19 with Create React App.
- React Router DOM for public, protected, admin, staff, and student routes.
- Redux Toolkit for auth, users, and lecture-related slices.
- React Context providers for auth, socket, dashboard, language/theme, and toast behavior.
- Axios for Laravel API calls.
- Socket.IO client for live attendance events.
- Socket.IO server in `server.js` for local realtime relay.
- XLSX for Excel import/export.
- ZXing and native `BarcodeDetector` for student QR scanning.
- Recharts is installed for chart/report possibilities.
- React Helmet for page metadata.
- CSS, responsive CSS, and Tailwind utility classes are mixed.
- `lucide-react` and custom exported icons are used through `src/assets/icons`.


Top-Level Application Flow
--------------------------
Main entry files:

- `src/index.js`
  Mounts React into the DOM.

- `src/App.js`
  Composes global providers and the router:
  `LanguageProvider -> ReduxProvider -> AppProviders -> BrowserRouter -> AppRoutes`.

- `src/routes/AppRoutes.js`
  Defines root route behavior:
  - `/` renders public sign-in routes.
  - `/dashboard/*` renders protected admin/staff/doctor dashboard routes.
  - `/student/*` renders protected student routes.
  - unknown paths redirect to the current user's landing path.


Global Providers
----------------
`src/providers/AppProviders.js` wraps the app with:

- `AuthProvider`
  Exposes auth state, login, sign out, user refresh, user management, and computed landing paths.

- `SocketProvider`
  Creates and exposes the Socket.IO connection after sign-in.

- `DashboardProvider`
  Stores dashboard runtime state such as sidebar state, active lecture, selected course/type/group/week, QR payload, live attendee list, and ended session records.

- `ToastProvider`
  Exposes success/error/info toast notifications.


Authentication And User State
-----------------------------
Main files:

- `src/redux/slices/authSlice.js`
- `src/services/authApi.js`
- `src/utils/Axios.js`
- `src/hooks/useAuthController.js`
- `src/providers/AuthProvider.js`

Authentication behavior:

- Sign-in sends `email`, `password`, `role`, `language`, and device metadata to Laravel.
- Student login sends a persistent device identifier stored in localStorage under `studentattend.auth.deviceId`.
- Successful login stores the returned user and token in Redux.
- Auth token is persisted in localStorage under `studentattend.auth.user`.
- Axios reads the token from localStorage and sends `Authorization: Bearer <token>`.
- Axios sends `Accept-Language` from `uniattend_lang`.
- On any API 401 response, Axios removes the stored auth user and redirects to `/` unless already on `/`.

Exposed auth controller features:

- `signInWithCredentials(credentials)`
- `signOut()`
- `updateUser(updates)`
- `refreshUsers()`
- `addAdmin(admin)`
- `updateAdmin(adminId, updates)`
- `deleteAdmin(adminId)`
- `addDoctor(doctor)`
- `updateDoctor(doctorId, updates)`
- `deleteDoctor(doctorId)`
- `addCourse(doctorId, course)`
- `deleteCourse(doctorId, courseUid)`
- `addStudent(student)`
- `updateStudentRecord(studentId, updates)`
- `deleteStudent(studentId)`
- `replaceStudents(nextStudents)`

Role routing:

- Admin users land on the first admin dashboard route they can access, normally `/dashboard/admin`.
- Staff/doctor users land on `/dashboard`.
- Student users land on `/student`.

Realtime And Persisted Attendance Flow
--------------------------------------
Main files:

- `server.js`
- `src/hooks/useSocketController.js`
- `src/hooks/useDashboardController.js`
- `src/Dashboard/pages/DoctorDashboard`
- `src/StudentApp/index.js`
- `src/utils/api.js`

Socket behavior:

- Socket server runs on port 3001.
- Frontend connects to `SOCKET_URL`.
- User role decides socket query:
  - student users connect with `clientType=student`.
  - dashboard users connect with `clientType=dashboard`.

Backend attendance behavior:

- Starting a lecture calls `lectureSessionsAPI.start`.
- Laravel creates a persisted `lecture_sessions` row and returns a QR payload.
- The QR payload includes `sessionId`, course code, lecture type, group, week, and issued time.
- Student scans call `attendanceAPI.scan`.
- Laravel validates the session, active status, QR payload values, student registration, group, and type.
- Laravel creates one `attendance_records` row per student per session.
- Student history calls `attendanceAPI.mine`.

Socket events still support live dashboard updates:

- `lecture_started`
  Emitted after backend session creation succeeds.

- `lecture_ended`
  Emitted after backend session end succeeds.

- `student_attended`
  Emitted by StudentApp after QR scan and relayed to dashboards.

Dashboard runtime state:

- Live scanned students are kept in dashboard context.
- Each scanned student is deduplicated by `universityId`.
- Ending a lecture stores the current live attendance list into `allSessions`.
- Session keys use:
  `COURSE__TYPE__GROUP__WEEK`

Important limitation:

- The scan itself is persisted, but the admin/staff Attendance and Reports pages still use frontend runtime/demo data for review/export. A dashboard attendance query API should be added before relying on those pages as the permanent record.

Import And Export Features
==========================
Admin doctor import:

- File parser:
  `src/Dashboard/pages/AdminPanel/utils/importWorkbook.js`

- Supports importing doctor/staff records and assignments.
- Supports downloading a template workbook.

Student import:

- File parser:
  `src/Dashboard/pages/StudentsPage/utils/importStudentsWorkbook.js`

- Supports parsing student records and registrations.
- Shows preview before applying upload.

Attendance export:

- Attendance Records exports selected week or all sessions for a course.
- Attendance Reports exports filtered report rows.
- Export format is XLSX.


Known Current Limitations
=========================
- Some screens still use in-memory demo data mixed with API data.
- Completed lecture display sessions are stored in frontend state and are lost on refresh, even though backend scan records persist.
- Attendance and Reports dashboard pages do not yet query persisted backend attendance records.
- Courses Page uses local state and does not persist to the backend.
- Tickets pages exist but are not routed.
- Some Arabic text files contain mojibake; runtime recovery exists for many translated values.
- The admin route list includes a QR item in metadata, but no `/dashboard/qr` route is currently registered.
- `lectureSlice` exists but current live lecture state is primarily handled in `useDashboardController`.
- Student profile updates currently update frontend auth state and may not persist to backend unless extended.
